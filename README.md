# 保供台账（本地可续作）

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 逻辑测试：`npx tsx test-logic.ts`

油站保供台账，支持断线改派、恢复后按字段基线合并、重复改派幂等、冲突两版待处理。地图、库存统计、待处理清单读取同一份已确认结果。

## 核心机制

### 1. 油站登记
每站登记：安全库存、可用车位（每时段容量）、保底油量、当前库存。库存低于安全库存预警，低于保底油量标红。

### 2. 改派先占用目标站车位
改派时先校验目标站目标时段的车位容量：
- 有容量：原子生效（释放源车位 + 占用目标车位）。
- 容量不够：保留原派单，返回最早可用时段（从目标时段起向后找第一个有空位的时段）。

### 3. 断线操作进入待同步队列
断线时改派操作进入待同步队列（`pending`），恢复网络后自动同步。同步中模拟网络往返（每条 250ms）。

### 4. 恢复后按站点、车次和字段基线合并
同步时对每个被改派的字段做 3-way 合并：
- 基线（baseline）：操作创建时的字段值。
- 本地改派版（payload）：期望改到的字段值。
- 服务端现行版（current）：当前已确认的字段值。

对每个字段：
- 本地改了、服务端没改 → 采用本地版。
- 本地没改、服务端改了 → 采用服务端版。
- 两边都改了且一致 → 采用该值。
- 两边都改了且不一致 → 冲突。

### 5. 重复改派只生效一次（幂等）
每个改派操作有幂等键（`reassign:车次:目标油站:时段`）。同步时若同幂等键的操作已确认，新操作标记为 `duplicate`，不再生效。

### 6. 同一车次两边都改过 → 保留两版待处理
冲突时：
- 派单状态置为 `conflict`，冻结（不能继续改派）。
- 保留本地改派版和服务端现行版。
- 待处理清单显示冲突，用户选择保留本地版或采用服务端版。
- 处理后派单恢复 `confirmed`，相关冲突操作标记已确认。

### 7. 失败后保留原操作，可重试
容量不够等失败情况：
- 在线：失败操作入队（`failed`），显示最早可用时段，可点击重试。
- 断线：操作入队（`pending`），恢复后同步。

### 8. 已确认派单不能回退
已确认派单只能通过改派流程变更，不能直接删除或回退。改派失败时派单保持已确认状态。

## 数据持久化
所有数据（油站、派单、操作队列）保存在浏览器 localStorage（key：`hxwlfront-21-supply-ledger`）。刷新页面后自动恢复。

## 项目结构
```
src/
├── ledger/
│   ├── types.ts      # 类型定义
│   ├── seed.ts       # 种子数据（油站、车次、时段表）
│   └── store.ts      # Pinia store（车位计算、3-way 合并、幂等、冲突、同步队列）
├── components/
│   ├── StationMap.vue      # 油站地图（读取已确认结果）
│   ├── StationStats.vue    # 库存统计（读取已确认结果）
│   ├── DispatchList.vue    # 车次派单列表 + 冲突处理
│   ├── ReassignForm.vue    # 改派表单（车位提示）
│   └── SyncQueue.vue       # 待同步队列（重试、在线切换）
└── App.vue
```
